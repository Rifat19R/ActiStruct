- **OOM on the first real relax attempt:** Rifat ran `pw.x` on `ferrocene_initial.in` and hit `MPI_ABORT`. Two issues, fixed in sequence: (1) he'd used a nonexistent input path (`qe_inputs/initial_relax/ferrocene.in` vs. the real `qe/inputs/relax/ferrocene_initial.in`) - confirmed via QE's own `CRASH` file; (2) after fixing the path, the job ran but needed an estimated 54.79 GB total dynamical RAM against 16 GB WSL + 20 GB swap on a 32 GB host, and briefly destabilized the WSL VM. Root cause: `vacuum_padding_angstrom: 12.0`/side inflated the cell to ~28.3 A for a ~4.5 A molecule. Reduced to `6.0` (still standard for `assume_isolated='mt'`), regenerated all 4 `.in` files, re-verified ferrocene against the real `pw.x` binary - ran cleanly through several SCF iterations (energy -525.36 -> -524.93 Ry) at an estimated ~10.5 GB/process.
- **cr_co6 BFGS convergence failure (real data):** Rifat ran the sequential queue (ni_co4 -> cr_co6 -> fe_co5). ni_co4 and fe_co5 converged cleanly (`bfgs converged in 9/13 scf cycles`, final energies -583.5691160575/-629.6772928617 Ry). cr_co6 exited 0 but actually failed: `bfgs failed after 10 scf cycles and 7 bfgs steps, convergence not achieved` - exit code 0 does not mean converged, QE still prints `JOB DONE` on a failed-to-converge BFGS run. Traced the trajectory: `Total force` dropped to ~0.0004 Ry/au (close to `forc_conv_thr=1e-4`) but the trust radius collapsed below QE's default `trust_radius_min` floor and BFGS gave up. Root cause: `ibrav=0` (QE itself flagged this `DISCOURAGED`) used a generic `CELL_PARAMETERS` matrix that can carry tiny floating-point asymmetries showing up as force noise near a symmetric stationary point - `cell_type: cubic_supercell` should have mapped to `ibrav=1`/`celldm(1)` from the start. Fixed both: `ibrav=1` everywhere, plus `trust_radius_min` lowered to `1.0e-6` bohr (new `ion_trust_radius_min_bohr` config key) so BFGS doesn't abort prematurely. Applied to all 4 systems in `scripts/06_build_qe_inputs.py`, re-verified with smoke tests (no parse errors, same symmetry/RAM as before), `tests/test_qe_input_builder.py` now asserts the new content. 28/28 tests still pass.
- **ferrocene crashed writing its checkpoint, root cause was the 9p mount:** Rifat reran ferrocene separately - SCF actually converged cleanly (38 iterations, energy -525.34303376 Ry, "convergence has been achieved") but then `Error in routine create_directory (1): unable to create directory /mnt/d/.../ferrocene_initial.save/`. `mount`/`df -T` confirmed `/mnt/d` is 9p (DrvFs) in WSL2, known-unreliable for concurrent multi-MPI-rank directory creation - exactly QE's checkpoint-write pattern. `/home/duets` is native ext4. Applied to all 4 systems, re-verified with a cr_co6 smoke test (no errors, same RAM estimate, `.save/` created cleanly on native fs). `tests/test_qe_input_builder.py` now asserts `outdir` never points at `/mnt/d`. 28/28 tests pass. Also noted in passing: `D:` is at 90% capacity (19GB free) - not the cause here, but worth watching.
